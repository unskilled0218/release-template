## Scope

Fix B1–B3 from `tasks/9-publish-images-readable-releases/5-code-review.md`: link authorization can expire during the last version lookup, a durable pending tag intent can outlive its unrooted Git object, and current filesystem symlinks can block valid historical note blobs. Implement narrow fixes with deterministic local regressions, preserving publication identity, exact-pin retries, committed project notes, explicit linking authority, and guarded local/remote cleanup.

The current engine is 0.2.5. Task 9 recorded 230 passing tests and successful approved v0.2.5 publication/runtime/retry/local-removal checks. Those results are a baseline, not evidence that these three edge cases are covered. This task plans a patch update to 0.2.6. It does not authorize another live release, remote push/link/delete, historical tag/body edit, old-pin checkpoint adoption, or removal of preserved live resources. Planning changes only this file.

## Implementation Plan

### 1. Enforce package-link authority at dispatch

- Refactor `release_template/linking.py` so loading/validating authority, checking the deployed server, and deciding whether the window is active are explicit steps. Retain the bounded strict schema-1 record, duplicate/unknown-field refusal, exact origin/full-version/owner/repository/configured-name scope, confirmed operator exclusion, and bounded UTC interval. Preserve inclusive start, exclusive expiry, and the maximum 24-hour duration.
- Read the operator file once for each attempted mutation and capture one validated canonical snapshot plus its digest. Use that same snapshot for all scope/server checks, the durable `link_windows` evidence, and the eventual POST decision. Do not reread/replace authority implicitly during the attempt or accidentally persist one window while dispatching under another. A replacement/renewed file is considered on a subsequent attempt; it does not silently extend the captured window.
- Keep `link:<image>` intent and its immutable owner/name/repository/prepared-digest details unchanged. With an unlinked package, perform potentially blocking server-version validation and the final complete/scoped association checks before the mutation-time decision. If fresh evidence already matches, reconcile completion without another POST. Foreign, missing, malformed, or contradictory evidence must still stop later publication writes.
- Before a necessary POST, append the exact authority snapshot/digest to separate attempt evidence and durably flush it. Then perform a pure active-window check using a fresh clock reading, after all preceding file reads, network lookups, and persistence. Call `Gitea.link_package` immediately afterward, with no intervening authority-file reread, server request, association request, completion flush, or other blocking validation. A failed final time check leaves intent pending and issues no POST, tag push, final promotion, or release POST.
- Preserve fresh post-link confirmation and accepted-but-response-lost reconciliation. If a response arrives after a valid dispatch's window expires, do not erase the already accepted operation or attempt an unauthorized rollback; reconcile its actual association. A confirmed matching retry needs no new authority or POST. Any still-unlinked mutating retry requires its own freshly loaded, valid snapshot, without changing immutable intent or rebuilding images.
- Document the precise guarantee: the engine checks authority immediately before dispatch, not atomic wall-clock completion of a remote request. Actual operator-established exclusion must remain effective through in-flight completion/confirmation. This fix does not turn a JSON record or checkout-local lock into a distributed lock, provide API compare-and-swap, or prove other writers are disabled.

### 2. Recreate only the approved annotated object

- Use the existing deterministic tag serialization in `release_template/git.py` rather than introduce private Git refs, new retention rules, or a new checkpoint schema. Preserve the exact marker, canonical schema-2 identity, direct commit target, declared tag name, and fixed tagger identity/epoch timestamp. Reissuing `git mktag` with those exact bytes is a local content-addressed operation, not a new publication or changed annotation.
- In `Workflow.tag_source`, derive and validate the expected identity from the same captured source/config/template/notes/prepared outputs. If tag intent exists, first check its tag, commit, complete intended identity, and recorded object-ID shape against this transaction. Do not change stored intent to fit regenerated data.
- Create/ensure the deterministic object locally for both new and existing intents before inspecting it. For existing intent, require the resulting object ID to equal the recorded ID exactly, then inspect and compare the complete identity. Do not route successful regeneration through the current inspect-a-missing-object-first path. A mismatch, malformed intent, object/command failure, local tag conflict, or conflicting annotation stops before remote mutation; local tag refs are never overwritten.
- Keep `State.intent` equality enforcement and durable intent-before-push ordering. Once the exact object is available, reconcile the advertised remote object, peeled commit, and intended identity as before. A matching remote tag completes pending intent without another push. An absent pending tag may receive only the recorded object with an ordinary non-force push. A completed tag that disappears, a foreign object, or a lightweight/conflicting tag remains a refusal, not repair authority.
- Do not broadly catch Git/authentication/transport errors as object absence. Deterministic reconstruction avoids needing an error-prone missing-object classifier; it must not become permission to rebuild images, regenerate another annotation, rewrite checkpoints, force tags, or auto-adopt an older template pin.

### 3. Read historical notes independently of the worktree

- Introduce a small pure lexical Git-relative-path validator in `release_template/core.py`, reusable by the note adapter and identity policy. Require a nonempty relative POSIX path, reject absolute paths, parent-traversal components and NUL, and preserve exact accepted path text for tree-entry comparison. It must not call filesystem resolution, inspect symlinks, require current file existence, or read through the current checkout. Avoid unrelated path-format tightening.
- In `Runner.git_blob`, replace the call to filesystem-aware `child(self.root, path)` with lexical validation. Query the requested commit's tree with a literal pathspec and NUL-separated output. Require one exact matching filename with regular blob mode `100644` or `100755`; reject symlinks, gitlinks/submodules, directories, missing entries, wildcard-expanded alternatives, and traversal. Intermediate symlinks in the captured tree must not be followed.
- Continue reading the selected blob by its object ID, with the existing size limit, bounded subprocess, UTF-8/version-heading validation, narrow newline normalization, and note digest/body comparison. A current symlink, missing path, directory, or different content cannot supply bytes or invalidate a regular blob in the requested historical commit. Captured-tree symlinks remain invalid even if the current path later becomes regular.
- Reuse the lexical validator in schema-2 notes-path validation to keep the committed-path rule in one place. Keep `child()` and its existing symlink protections for real working-tree/configuration/build/update destinations. Do not weaken active configuration safety, Git destination checks, or source cleanliness requirements to accommodate historical reads.

## Acceptance Criteria

- B1: A window that expires during server validation, final association evidence, or durable persistence cannot dispatch a link POST. Dispatch uses the same canonical authority that was recorded. Start is inclusive, expiry exclusive, and confirmed matching retries need no duplicate POST. Operator-established exclusion remains a required external precondition through request completion.
- B2: After pending annotation pruning in a controlled repository, same-pin recovery recreates only the exact checkpointed tag object and resumes without rebuilding or repeating confirmed remote mutations. Different object/identity/local or remote tags fail closed; no force update, checkpoint rewrite, automatic tag repair after confirmed disappearance, or old-pin adoption occurs.
- B3: Valid historical regular note blobs remain verifiable from a different clean current tree, including one with symlinks at the old path. Captured symlinks, malformed/traversing/literal-mismatch paths, and invalid note bytes/bindings remain rejected. Real filesystem destination protections stay intact.
- Existing project-only descriptions, complete image/digest/platform identity, legacy reading, monotonic ownership, source/config/template pin checks, package association confirmation, local-image protection, and remote deletion gates continue to pass their regressions.
- Local tests, launcher/configuration checks, docs anchors, version agreement, and diff checks pass. Implementation records actual evidence and limits. Published v0.2.3/v0.2.4/v0.2.5 history, live checkpoint provenance, remote artifacts, and `todo.md` remain untouched.

## Risks And Decisions

- An immediately preceding clock check cannot make network dispatch/completion atomic with a UTC deadline. This fix closes the reproduced blocking-validation gap and defines dispatch-time authority honestly; actual exclusion must still cover in-flight requests and external writers.
- Capturing authority once avoids inconsistent evidence from repeated file reads. A file replacement is not an implicit mid-attempt renewal or revocation protocol; use a fresh attempt for a new record, and do not end real writer exclusion while an approved operation is in flight.
- Deterministic reconstruction is chosen over private refs because the current canonical tag bytes already encode the approved identity. The stored object ID remains authoritative; reproduction of equivalent meaning with different bytes is not acceptable. Git errors remain failures, not absence signals.
- Historical Git blobs are not working-tree files. Removing current-filesystem checks from that one object-reading boundary does not justify weakening filesystem checks elsewhere, accepting captured symlinks, or following outside paths.
- These fixes improve future transactions under the new pin. They do not make new code compatible with already captured old-pin checkpoints or authorize rewriting them. Live image availability and remote deletion semantics are not established by synthetic recovery tests.
