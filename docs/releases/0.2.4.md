## Changes

Release descriptions now contain committed project updates rather than generated verification records. Publication verifies those records separately and preserves build-once recovery. Repository package association is an explicit, confirmed operation with a scoped single-writer prerequisite. Optional local finalization records ownership across retries and protects pre-existing, shared, and container-used content.

## Compatibility and upgrades

Consumers must configure and commit their own version-matched release notes before publishing with this pin. Existing recognized legacy releases remain readable without rewriting historical descriptions or tags. Preserve the original source, configuration, template pin, and checkpoint when resuming an existing transaction. Remote deletion still requires separate approval and fresh deployment-specific verification evidence.
